# NIMENA Journals Public Audit — 27 September 2026

## Scope and limitation

This is a public, read-only review of `https://nimenajournals.com`. It does not replace an administrator audit of the database, files, plugins, email, scheduled tasks, backups or editorial records.

The public site identifies itself as Open Journal Systems 3.5.0.3 and uses the `ogNova` theme. Administrator access and a verified backup are required before any journal-system changes.

## Immediate findings

| Priority | Finding | Required action |
| --- | --- | --- |
| Critical | The public journal site uses “Nigerian Institute…” in places instead of the official “Nigerian Institution…”. | Confirm the legal/brand name and correct it consistently. |
| Critical | JBESED ISSN values conflict between public sections of the site. | Verify against official ISSN records and correct every display and metadata field. |
| Critical | DOI examples appear to use placeholder-style prefixes. | Confirm the DOI registrant, prefix and deposit status before displaying DOI claims. |
| High | Some About/policy navigation crosses from `nimenajournals.com` to `nimenajournals.org`. | Confirm the canonical domain, redirects and ownership; update all internal links. |
| High | Unverified citation, h-index, i-index and indexing/preservation claims are displayed. | Retain only claims supported by the relevant provider or registry. |
| High | Public counters conflict with surrounding text, including zero-value counters. | Drive counters from real data or remove them. |
| Medium | “Announcements” is misspelled as “Accouncements”. | Correct the label and review visible copy. |
| Medium | Sampled responses expose the PHP version and did not visibly return common browser security headers. | Review server disclosure and add/test appropriate HSTS, CSP, MIME sniffing and referrer protections without breaking OJS. |

## Recommended remediation order

1. Create and verify a full backup of the OJS database, uploaded files, configuration and custom theme/plugins.
2. Clone the installation into a non-public staging environment and test restoration.
3. Inventory the OJS core version, PHP/database requirements, installed plugins, custom code, cron jobs and mail settings.
4. Confirm the canonical domain and enforce HTTPS/redirects without disrupting email or DNS records.
5. Verify each journal's official name, abbreviation, ISSNs, publisher, ownership, contacts and editorial board.
6. Verify DOI registration and deposits; correct or remove placeholder and unsupported DOI fields.
7. Verify every indexing, preservation, citation and performance claim.
8. Configure complete author, reviewer, ethics, appeals, corrections, retractions, licensing, privacy, APC and waiver policies.
9. Review roles and remove dormant or excessive administrator/editor permissions.
10. Test one fictional manuscript through submission, screening, review, revision, acceptance, copyediting, production and publication.
11. Redesign the theme on staging using NIMENA's restrained navy/orange/white system and accessible mobile navigation.
12. Run security, accessibility, email-delivery, backup and rollback tests before production release.

## Information required from NIMENA

- OJS administrator and hosting control-panel access
- Current backup location and retention schedule
- Official journal registration/ISSN documents
- DOI provider account and registered prefix
- Editorial-board appointments and role owners
- Approved publishing, ethics, fee and copyright policies
- Existing submission and issue inventory
- Canonical domain decision for `.com` and `.org`
- Outgoing mail configuration and a safe test mailbox

## Change-control rule

Do not edit the live OJS database, upgrade plugins or replace the theme until the backup has been restored successfully on staging. All editorial records and published URLs must remain intact during redesign.
